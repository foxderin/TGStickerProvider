# 有界并发、透明解码与来源选择

## 当前行为

- 全进程共享最多 **8 个转换工作线程**，每轮最多 8 个在途任务，不为每个包各建一个线程池。Android `isLowRamDevice` 为真时窗口降为 2。
- 并行任务只读取来源、验证缓存或生成唯一临时文件；协调者按原始顺序逐一发布。同步、删除和清缓存共用一个进程内存储锁，检查/原子替换/凭证/旧版本清理不会跨同步任务交错。
- 原有 SHA-256 来源/产物/recipe 缓存保留；命中不启动 FFprobe/转码。格式、解码库及 GIF 配方变化会使相关视频缓存失效。
- 每个完整 ID 只选择一个来源。按包保存“优先高清/优先低清”，缺少所选档时使用另一档。它不是缩图开关；Hook 常会删除被高清替代的低清来源，因此不能保证总有低清可选。
- Hook 在旧的 4 行元数据后追加原始 sticker ID 顺序，兼容旧读取格式。新元数据存在时按该顺序发布/设置时间戳；旧元数据回退为确定性的 ID 顺序，不宣称恢复了原始顺序。消费端是否按 mtime 排序不由本应用保证。
- “只显示待同步”在后台使用同一来源选择、格式、recipe 和内容指纹判断，不再把文件数量当作完成证明；只有启用此过滤器才计算，不在 UI 线程哈希，也不在批量同步每一包之后重复检查全库。

## GIF 默认与实验 APNG

使用 `ffmpeg-kit-video:6.0.6`；探测来源 codec 后 VP9 选择 `libvpx-vp9`，VP8 选择 `libvpx`。缺少 libvpx 或其他 codec 会明确失败，不静默换回可能丢透明的解码路径。

GIF 仍是默认格式，普通档仍为 320px/10fps，高清档保留来源尺寸/帧率。普通 GIF 改为先减帧/缩放再生成调色板，保留 GIF 能表达的二值透明；这会改变普通档的色彩、体积和耗时，不声称“零代价优化”。GIF 不能保留连续半透明。

APNG 必须手动启用，界面明确标记实验与接收端要求。它输出 RGBA 动画 PNG（文件扩展名 `.png`），保留来源尺寸/帧率。本次未验证当前 QQ 自定义目录的动画消费行为，没有真实 QQ 导入测试，接收端可能只显示首帧。

解码/编码及 FFmpeg filter 工作线程设置为 1，限制同时运行多个 session 的内部线程膨胀。这不是所有平台线程总数上限，也不是硬件加速。未改变图片分辨率来制造并发提速。

## 失败、生命周期与内存边界

- 来源转换前后及发布前检查指纹；外部 Telegram Hook 在另一个进程，无法共享本应用锁，因此没有声称对外部写入提供文件系统事务隔离。
- 失败保留旧目标，临时文件不计入贴纸数。下次同步在锁内清理上次进程死亡遗留的 `.convert-*.tmp`。
- 任一 prepare 失败以结果返回，其他项目继续。协调者中断/消费失败会等待所有已提交 native 任务结束并清理尚未消费的临时产物，之后释放锁，恢复中断标记。
- 不把 Future.cancel 当作 native FFmpeg 已停止；没有新增立即取消或超时承诺。Activity 销毁后当前包安全完成，不再启动后续包或弹出结果对话框。
- 启动新的重型转换前检查系统 `MemoryInfo.lowMemory`，低内存则报错并保留旧目标。加上低 RAM 设备降并发，这只是保护措施，不保证 8 个任务绝不会遇到 native OOM；实际手机内存、发热与性能仍需验证。

## 验证与发布限制

临时 JVM harness 覆盖：8/2 窗口、按序消费、准备失败继续、消费失败/中断后的资源排空、清理异常聚合、存储锁排他、12/123 ID 隔离、高低清/格式选择、旧/新顺序元数据、VP8/VP9 分支、recipe 差异和互斥凭证发布。这些是临时检查，不是新增到仓库的回归测试。

使用实际 Kotlin 参数生成函数调用主机 FFmpeg，3 秒合成透明素材验证：普通 GIF 30 帧/3 秒并保留二值透明；高清 GIF 90 帧；APNG 90 帧并保留半透明像素。它是参数与输出性质检查，不是 Android 性能测试或 QQ 兼容性认证。

许可证/对应源码信息仍有明确缺口，见 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)。本地 APK 构建通过不能视为允许发布；未确认完整 native notices/对应源码前，不发布这次新增依赖的 APK。

最终集成验证：debug/release APK 构建、现有 JVM 示例测试（1/1）、instrumentation APK 编译、lint 均通过；lint 49 条警告、无错误。合并运行 lint/R8 时曾遇到 Gradle daemon 意外退出，拆分执行并限制构建 workers 后完成验证，没有把构建失败归因成手机并发性能。Debug/release ZIP 均通过 16KB 对齐检查，最终 APK 仅包含 arm64-v8a，10 个原生库 ELF LOAD 对齐至少16KB。打包的42个上游notice资产哈希与sources.json一致，不代表已填补上述许可缺口。

额外主机检查：VP8透明WebM通过libvpx输出6帧APNG，并保留透明及半透明像素；仍不是Android native执行或QQ消费端测试。
